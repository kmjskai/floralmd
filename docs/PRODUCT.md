# FloralMD 产品需求与验收总表

本文给产品负责人用于确认 FloralMD 应该呈现的长期行为。工程实现与证据分别见 [ARCHITECTURE.md](ARCHITECTURE.md) 和 [PROGRESS.md](PROGRESS.md)。`[x]` 表示已有自动化或人工证据，`[ ]` 表示仍需实现或手测；不以“代码已写”代替验收。

## 2026.9.1 公开版重构边界

`2026.9.1` 以已经锁定的本地工作区编辑器为实现基线，并继续使用 FloralMD 作为唯一公开产品名。它是旧版 FloralMD 的重大改版，不是旧界面的逐项复刻。

- 保留并公开本表描述的 Markdown、图片和 Excalidraw 编辑能力。
- 不恢复旧版 Git 状态／提交／历史面板、侧边语义 Map／Minimap、原生多文档标签页、附近文件栏、Files／Git 双侧栏和旧版 Markdown 扩展开关。
- macOS 版本沿用 `com.yingkaisun.floralmd` 与既有更新通道；开发版使用隔离身份 `com.yingkaisun.floralmd.dev`。
- 既有 FloralMD iOS 版本不在本次 macOS 重构范围内。
- SlateMemo 只作为实现来源与历史名称保留，不再作为独立公开品牌发布。

## 1. 开始记录

### WS-01 Draft 工作区

**用户场景**

用户启动 FloralMD、创建新内容，或尚未指定要打开的文件。

**预期行为**

FloralMD 使用用户选择的 `FloralMD Drafts` 文件夹作为默认工作区，并按用途维护以下结构：

```text
FloralMD Drafts/
├── notes/
│   └── assets/
│       └── images/
└── drawings/
    └── exports/
```

**验收清单**

- [x] 缺失目录可以按上述结构创建。
- [x] 目录名称按用途区分，不创建新的 `excalidraw/` 目录作为标准结构。
- [ ] 首次启动选择 Draft 根目录的界面与取消路径已人工验证。

### NEW-01 新建 Markdown

**用户场景**

用户从工具栏、菜单、命令面板或快速记录入口新建笔记。

**预期行为**

新 Markdown 保存到 Draft 的 `notes/`，文件名安全且不覆盖已有文件。

**验收清单**

- [x] 默认目标为 `notes/`。
- [x] 同一秒连续新建会递增文件名且不覆盖。
- [x] 编辑内容可原子保存，切换资源前会先保存脏 Markdown。
- [ ] 四个入口均在统一窗口中选中新文件，待人工验证。

### NEW-02 新建绘图

**用户场景**

用户从工具栏、菜单或命令面板新建绘图。

**预期行为**

新绘图以 Draft 的 `drawings/` 为目标，并在统一窗口中央进入绘图画布；仅进入画布时不预先制造空源文件。

**验收清单**

- [x] 默认目标位于 `drawings/`，且占位选择不会创建文件。
- [x] 从已有绘图新建时会重置画布与绘图身份，不复用上一张绘图。
- [ ] 各入口均切换到中央画布，待人工验证。

## 2. 打开与浏览文件

### OPEN-01 打开 Draft 内文件

**用户场景**

用户打开 Draft 内任意受支持文件。

**预期行为**

FloralMD 打开整个 Draft 工作区，并在侧栏与中央区域选中目标文件。

**验收清单**

- [x] Markdown、`.excalidraw`、PNG、JPG、JPEG、GIF、WebP、SVG 都能识别。
- [x] Draft 子目录中的目标仍解析为同一个 Draft 根。
- [ ] 从 Finder 双击每种格式后的窗口与选中状态，待人工验证。

### OPEN-02 打开外部文件

**用户场景**

用户打开不在 Draft 内的受支持文件。

**预期行为**

该文件所在文件夹成为临时工作区，目标被选中；FloralMD 不猜测更高层根目录，也不创建 `.floralmd`。

**验收清单**

- [x] 工作区根严格等于目标文件的父文件夹。
- [x] 不自动创建元数据文件或搬移资源。
- [x] 外部目录权限使用该工作区根的安全书签恢复或明确授权。
- [ ] 授权、取消授权与重新打开流程，待沙盒构建人工验证。

### OPEN-03 明确打开工作区

**用户场景**

用户从 File 菜单、命令面板或空状态选择一个文件夹。

**预期行为**

用户选择的整个文件夹成为该窗口的显式工作区根；不改动 Draft 默认位置，不复制、迁移或扫描根目录之外的内容。空且无未保存内容的窗口可原位切换；有活动资源或未保存内容时新建窗口。同一根已打开时激活现有窗口。

**验收清单**

- [x] 显式工作区、窗口恢复值、空/非空窗口策略与多窗口关闭 ownership 有自动化覆盖。
- [x] 文件夹书签复用现有 `FolderAccessService`；恢复、无效书签和不可读目录有明确错误路径。
- [x] File 菜单、命令面板与空状态复用同一 focused action。
- [ ] 空窗口原位切换、非空窗口新开、同根激活、重启恢复与失效授权待签名沙盒构建人工验证。

### BROWSE-01 统一工作区侧栏

**用户场景**

用户希望在当前工作区内浏览并切换不同格式的资源。

**预期行为**

侧栏递归显示工作区中的普通文件夹和普通文件；受支持资源可在统一编辑区打开，其他普通文件仍可用于 Quick Look、Finder 与文件操作。隐藏项、Finder package 与符号链接不进入树，FloralMD 不跟随它们扩大授权边界；不可读子目录保留目录行并显示受限状态。资源变化后可刷新。

**验收清单**

- [x] 递归目录中列出受支持资源及其他普通文件；隐藏项、package 与符号链接跳过。
- [x] 文件夹在文件前，名称按自然顺序排列。
- [x] 新建、绘图保存与图片落盘会触发合并刷新；外部改名/删除后按文件身份稳定选择并保留目录展开状态。
- [x] 活动资源被外部改名时切换到新 URL；被删除或移出工作区时阻止继续保存旧路径并显示状态。
- [ ] 展开、选中、刷新和 Finder 右键操作，待人工验证。

## 3. 在一个窗口中工作

### FILES-01 安全文件操作

**用户场景**

用户在 Files 侧栏中新建 Markdown 或文件夹，并对普通文件或目录执行重命名、制作副本、移动或移到废纸篓。

**预期行为**

所有写操作集中由 `WorkspaceFileOperationService` 执行并限定在当前授权工作区；同名目标一律报错，不静默覆盖。删除仅使用系统废纸篓。当前 Markdown 或其父目录变更前先保存，成功后活动 URL、选择与窗口标题指向新位置。活动绘图无法由文件服务判断画布 dirty 状态，因此影响它的操作会要求先保存并切换离开。`.excalidraw` 与 SVG 始终是两个独立普通文件。

**验收清单**

- [x] 新建 Markdown/文件夹、重命名、制作副本、跨目录移动与废纸篓服务边界有聚焦测试。
- [x] 同名冲突、循环移动、大小写改名、父目录改名与活动 Markdown URL 更新有聚焦测试。
- [x] 非空文件夹在 UI 中确认；活动绘图操作明确阻止，不丢失画布。
- [x] `.excalidraw` 与 SVG 不联动改名、复制、移动或删除。
- [ ] 菜单、错误提示、权限失败、真实废纸篓恢复与窗口标题待人工验证。

### FILES-02 Finder 风格入口与单选边界

**用户场景**

用户在 Files 侧栏与 Finder 之间拖放文件，或在侧栏获得焦点时使用原生键盘与右键菜单完成单个项目的常用操作。

**预期行为**

工作区内拖到文件夹默认移动，按住 Option 复制；Finder 拖入一律复制到明确的目标文件夹，Option 不改变外部导入语义。所有目标都拒绝同名覆盖与目录循环，已知跨卷移动明确失败，不用复制后删除伪装移动。拖出发布标准 file URL。侧栏获得焦点时才响应剪切、复制、粘贴、Return、Delete 和 Space，Markdown 编辑器继续拥有文本快捷键。Quick Look 和“在 Finder 中显示”适用于受支持与不支持文件。

**验收清单**

- [x] 内部移动/Option 复制、外部导入、真实 pasteboard 标记、标准 file URL 拖出与冲突拒绝有聚焦测试。
- [x] 右键菜单提供 Quick Look、Finder、新建、重命名、制作副本、移动与废纸篓入口。
- [x] 本阶段明确为单选闭环；不实现批量操作、文件操作撤销或 Finder 全功能复刻。
- [x] `.excalidraw` 与 SVG 在拖放、剪贴板和菜单中仍按两个独立文件处理。
- [ ] 真实 Finder 拖入/拖出光标、Option、Quick Look、键盘焦点和沙盒权限待人工验证。

### SURFACE-01 统一窗口

**用户场景**

用户在 Markdown、绘图与图片之间切换。

**预期行为**

FloralMD 使用一个工作区窗口、一个侧栏和一套窗口工具；切换文件只替换中央内容，不再默认弹出独立绘图窗口。

**验收清单**

- [x] 应用入口不再以单个 Markdown 文档或独立绘图窗口作为窗口身份。
- [x] 中央内容由当前选中的资源类型决定。
- [ ] 连续切换三类资源时始终只有一个工作窗口，待人工验证。
- [ ] 标题、置顶、透明度和工具栏在各 Surface 间保持一致，待人工验证。

### MD-01 Markdown 编辑与预览

**用户场景**

用户选择 Markdown，并在实时编辑和只读预览之间切换。

**预期行为**

Markdown 保持标准 UTF-8 源文件；编辑支持既有实时样式、中文输入、大纲、链接、表格、代码、数学公式与 Mermaid；预览与当前内容一致。图片语法在编辑态保持可见、可选、可改，同时在源码行下方显示内联图片；编辑与只读预览使用同一套工作区内相对图片解析规则，支持 PNG、JPG、JPEG、GIF、WebP 与 SVG。路径以当前 Markdown 目录为基准，尚未落盘的 Draft 文档以 `notes/` 为基准。

实时编辑中的视觉表格可直接编辑单元格；单元格未聚焦时渲染正文已支持的 strong/emphasis/strikethrough、行内代码、行内公式、链接、图片与反斜杠转义，聚焦后显示并编辑原始 Markdown，退出后重新渲染。渲染不改源码，原始 HTML 只作文本显示，相对图片继续走工作区授权资源 scheme；`Command`-点击渲染链接沿用正文导航。任意单元格内按 `Command-Enter` 会在一次可撤销 transaction 中提交当前单元格内容，并把 Markdown 光标移到表后第一个普通正文位置；文档末尾的表格只补一个空正文行，已有正文或邻接空行时复用现有边界，不新增表格行或重复空行。表体左侧与表头上方提供克制的行/列把手，选中后可用 Delete/Backspace 删除；内部横向、纵向分隔线上的 `+` 分别在该位置插入行、列，底部中央和右侧中央的 `+` 继续负责末尾追加。表格单元格右键不提供专用结构菜单，也不拦截系统上下文菜单事件。表头不能按正文行删除，一列表格不能删除最后一列；插列必须同步表头、delimiter/alignment 与正文。所有结构控件仅在表格 hover、focus-within 或自身聚焦时显现，具有 VoiceOver 标签且不进入 Markdown 源码或搜索文本。只读预览不提供结构编辑入口。

实时编辑使用适度语义配色：正文与 H1–H6 保持系统主文字色，链接为系统蓝，图片引用为柔紫，行内代码为暖棕且保留背景，Markdown 标点为次级灰；不提供设置开关。gutter 的 H1–H6 保持中性，围栏代码内容显示暖棕 `CODE`，独立图片或图片画廊行显示柔紫 `IMG`，正文句中的内联图片不显示 `IMG`。selection、当前搜索命中和失败状态始终优先于语义色。

FloralMD 的 Markdown 标题只支持 ATX `#` 语法，不支持 Setext 下划线标题。正文后的 `---` 按分隔线显示，`===` 保留为普通文本；实时编辑、gutter、大纲与只读预览必须使用同一语义，避免输入列表 marker 时把上一行正文临时识别为 H2。引用块内的 Setext 形态（`> 标题` 后跟 `> ===`/`> ---`）与 CRLF 换行的文件同样不产生标题：下划线行按分隔线或普通文本显示，标题行保持段落。

删除线只认 `~~双波浪线~~`：`~单波浪线~` 按字面文本显示（Obsidian 将单波浪线读作下标，本应用暂不支持下标，保持字面以避免编辑与预览不一致）。

hashtag 在实时编辑与只读预览中使用同一 token 规则并以同一胶囊样式渲染：`#` 后跟 Unicode 字母/组合记号/数字/下划线/连字符，可选 `/` 分隔路径段；词内邻接（前置为字母、数字、下划线、`/` 或 `#`）不识别，反斜杠转义不识别（已知边缘差异：`\#tag` 转义因解析器在预览侧已消耗反斜杠而仍显示胶囊，编辑侧不显示），纯数字 `#123` 不识别，段不能全为连字符；标题与链接文本内的 `#` 不渲染胶囊，表格单元格、引用块与脚注内正常渲染。

frontmatter 只识别 YAML `---` 分隔块（`+++` 按 Obsidian 语义作为普通正文渲染，TOML 不被解析）；大纲同样只跳过 `---` 块。

行首输入无序列表 marker（`-`、`*`、`+`）后必须再输入一个空格才进入实时列表渲染：裸 marker（后无内容）保持普通正文——包括前一列表项之后的裸 marker 行（保留列表排版但无悬挂盒），因此中文输入法组合紧跟裸 marker 输入时不与任何渲染盒/widget 相邻、候选窗保持横排；有序与无序列表项内按 Tab 一律嵌套缩进一级（行按列表排版而非缩进代码块），光标落到 marker 后正文列（marker 前的光标统一跳到正文开始，marker 后的保持相对位置），继续输入保持嵌套；编辑光标由编辑器自绘（隐藏系统原生 caret，避免删除后旧位置残留固定光标残影），坐标跟随正文与滚动（含打字机模式居中跟随），颜色跟随正文；`- ` 渲染后输入中文时，marker 装饰与分隔空格占位在组合前后完全一致（零占位隐藏由 mark 而非 replace widget 承担，避免 WebKit 在组合期间重建 widget 结构而吞字/残留/候选窗异常），组合文本从悬挂盒右端（正文列）开始且逐字符位置稳定。`- ` 后按 Enter 续行 `- `，裸 `-` 后按 Enter 只是普通换行。只读预览与编辑态保持同一语义：行尾裸 marker 不渲染为 CommonMark 空列表项，而是保留列表排版的普通文本行（无悬挂盒）；有序列表与任务 marker 仍按 CommonMark 渲染。

实时编辑中存在普通非空文本选区时，选区触及的 Markdown 构造完整显露源码：多行列表逐行显示原始 marker 与 task marker，标题显示 `# `，强调、删除线、行内代码、链接、图片、围栏和表格不保留半个 delimiter，也不继续显示粗斜体、语义色、背景、圆角或交互 widget。为避免选区弹跳，标题保留原字号、行高和换行几何，列表保留缩进与间距，行内代码保留字体尺寸和透明尺寸占位；同一视觉行内的小间隙合并成连续高亮，但空白逻辑行和渲染出的图片预览不进入文字选区。反向选择、Shift 扩展与全选使用相同规则；选区折叠后恢复完整实时预览，普通光标仍只激活当前构造。复制结果始终是原始 Markdown；输入法 marked range 保持组合输入所需的稳定活动构造排版。

编辑态 `Command`-点击与预览态普通点击相对 Markdown 链接时，都由当前统一工作区窗口先保存脏文档，再切换到目标 `.md/.markdown/.mdown`；fragment 留在应用内定位。工作区外目标沿用文件夹授权，缺失、目录、符号链接逃逸与不支持类型不得替换当前文档；HTTP、HTTPS、mailto、图片和绘图维持各自既有路由。

当前活动 Markdown 在外部程序中被原地写入、原子替换或改名时，FloralMD 会同步磁盘最终内容。编辑器干净时自动载入并给出非阻塞提示，同时保留可用的 selection、滚动位置和一次可撤销边界；中文输入处于组合阶段时延后载入。编辑器已有未保存内容时绝不覆盖，必须明确选择“载入磁盘版本”或“保留当前版本”。保留后继续 dirty 并暂停自动保存，只有用户显式 `Command+S` 才覆盖磁盘；冲突未决、外部删除或移出工作区时均禁止自动保存。此能力只覆盖当前活动 Markdown，不扩展到 Excalidraw、图片资源或整棵目录数据库。

编辑态已加载图片的双击或 `Command`-点击会打开 FloralMD 自有的独立只读查看窗口；同一文件重复操作只激活已有窗口。普通单击仍定位图片源码，加载中、失败和不支持资源不会打开空窗口；图片外层即使是 Markdown 链接，点击图片本体也按图片语义处理，普通 Markdown 链接继续使用原链接路由。独立窗口根据图片固有尺寸和当前屏幕可见区域计算首次居中的合理大小，大图限制在可见区域约 84% 并适应窗口，小图不放大；用户调整过的尺寸、缩放和平移在重复激活时不重置。窗口复用 IMAGE-01 的适应窗口、1:1、缩放、平移和 SVG 矢量重绘，提供“在 Finder 中显示”，并以工具条按钮独立控制置顶且默认开启；这不改变主窗口、其他图片窗口或侧栏图片仍在中央 Surface 打开的语义。

**验收清单**

### IMAGE-01 图片只读预览

**用户场景**

用户在侧栏或 Finder 打开 PNG、JPG、JPEG、GIF、WebP 或 SVG。

**预期行为**

中央区域使用统一的内嵌图片查看器显示只读预览，不弹出独立窗口或启动外部“预览”App，也不提供会改写原文件的编辑操作。PNG、JPG、JPEG、GIF、WebP 与 SVG 使用一致的缩放和平移方式：触控板双指滑动或滚轮用于平移，触控板捏合或 `Command` + 滚轮以指针位置为中心缩放，按住拖动也可平移，并可选择适应窗口或 1:1 原始尺寸。双击切换显示尺寸时不出现网页式文本或图片选中高亮。

SVG 的 1:1 表示 WebKit 解码得到的 intrinsic viewport 中 1 CSS 单位对应屏幕 1 CSS point：绝对 `width`/`height` 优先；只有 `viewBox` 时使用其 viewport 尺寸；百分比尺寸有 `viewBox` 时仍以 `viewBox` 为准，无 `viewBox` 时使用 WebKit 的 `300×150` replaced-element 回落。超大或极小 SVG 不改写源文件。缩放时矢量内容通过增长实际布局尺寸重新绘制；PNG/JPEG/GIF/WebP 仍保持位图语义，SVG 中内嵌的 PNG/JPEG 也不会因此变成矢量。

**验收清单**

- [x] 六种扩展名进入图片资源类型，并统一进入中央区域的内嵌查看器路径。
- [x] 缩放范围、倍率显示、本地图片载入边界与查看器交互模板通过自动化验证。
- [x] PNG、JPEG、SVG 在 `760×540` 最小窗口内可见，且保持中央嵌入式只读预览。
- [x] 真实 WKWebView 在 100%、400%、800% 验证 SVG 布局重绘与 PNG 位图变换分流，并覆盖 `viewBox`、绝对/百分比尺寸、超大与极小画布。
- [x] SVG 高倍率布局按倍率、宽高比、窗口、DPR 与峰值内存动态预算；滤镜 fixture、DPR 1/2 和极端画布降级有自动化覆盖。
